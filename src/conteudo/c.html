Lógica e programação em C

As questões de C no ENADE quase sempre pedem a saída de um trecho de código, então o que mais rende é treinar o rastreamento à mão. Todas as saídas abaixo foram compiladas e conferidas.

Como rastrear código à mão

  1. Faça uma tabela com uma coluna por variável.
  2. Execute linha por linha e escreva o novo valor sempre que uma variável mudar.
  3. Em laços, anote o valor do contador em cada volta e teste a condição antes de entrar.
  4. Em recursão, desenhe a pilha de chamadas: desça até o caso base e depois volte somando ou multiplicando.

Ponteiros

Entenda o assunto

Pense na memória como uma fileira de caixas numeradas. Uma variável é uma caixa com um valor dentro. Um ponteiro é uma caixa especial que guarda o número de outra caixa, ou seja, um endereço. Dois símbolos resolvem quase tudo: &x ("o número da caixa de x") e *p ("o conteúdo da caixa que p aponta").

Como C passa os argumentos por valor (copia), uma função não consegue mudar a variável de quem a chamou. Para isso, passa-se o endereço e a função mexe no conteúdo com *. Na hora de rastrear, desenhe as caixas: uma para cada variável, com seta do ponteiro até a caixa para onde ele aponta.

&x é o endereço de x; *p é o valor guardado no endereço para onde p aponta.

int a = 5;
int *p = &a;
*p = 10;
printf("%d", a);   // imprime 10: alterar *p altera a

Passagem de parâmetros: C sempre passa por valor. Para uma função alterar a variável de quem chamou, ela precisa receber o endereço.

void troca(int *a, int *b) { int t = *a; *a = *b; *b = t; }
int m = 1, n = 2;
troca(&m, &n);     // agora m = 2 e n = 1
Pegadinha mais comumSe a função fosse void troca(int a, int b), ela trocaria apenas as cópias e m e n continuariam 1 e 2. Vetores são a exceção aparente: o nome do vetor já é um endereço, então a função consegue alterar os elementos.
Exemplo passo a passo

O que imprime este trecho?

  1. int a = 5, b = 8; int *p = &a; → a = 5, b = 8, p aponta para a.
  2. *p = *p + b; → o conteúdo de a vira 5 + 8 = 13.
  3. p = &b; → agora p aponta para b (a não muda).
  4. *p = 1; → b vira 1.
  5. printf("%d %d", a, b); imprime 13 1.
Como cai no ENADE

É a base de quase toda questão de saída de código em C: troca de valores com função, ponteiro apontando para variável ou para posição de vetor. Sempre desenhe as caixas antes de responder.

Vetores e aritmética de ponteiros

Entenda o assunto

Um vetor é uma fileira de caixas coladas uma na outra, todas do mesmo tipo. O nome do vetor guarda o endereço da primeira. Por isso v[i] e *(v + i) são a mesma coisa: "ande i caixas a partir do início e leia".

Ao somar 1 a um ponteiro, ele avança uma caixa inteira (o tamanho do tipo, como 4 bytes para int), e não 1 byte. Os índices começam em 0, então um vetor de n posições vai de 0 a n−1, e C não avisa se você passar do limite (comportamento indefinido).

O nome do vetor é o endereço do primeiro elemento, e v[i] é o mesmo que *(v + i).

int v[] = {10, 20, 30};
int *q = v;
printf("%d %d %d", *(q + 2), q[1], *q + 1);   // 30 20 11

Cuidado com *q + 1: primeiro pega o valor (10) e depois soma 1. Já *(q + 1) avança o ponteiro e dá 20.

Exemplo passo a passo

O que imprime?

  1. int v[] = {4, 8, 15, 16}; int *p = v + 1; → p aponta para v[1], que vale 8.
  2. *p vale 8.
  3. *(p + 2) é v[3], que vale 16.
  4. Saída de printf("%d %d", *p, *(p + 2));: 8 16.
  5. Bônus: sizeof(v) / sizeof(v[0]) dá 4, o número de elementos.
Como cai no ENADE

Cai misturado com ponteiros: o que imprime tal expressão com *(p+i), p[i] e *p + 1. A pegadinha clássica é confundir *p + 1 (valor mais 1) com *(p + 1) (próximo elemento).

Strings

Entenda o assunto

C não tem um tipo "texto" de verdade. Uma string é um vetor de char em que o fim é marcado por um caractere especial, o '\0'. As funções da biblioteca (strlen, strcpy, strcmp) andam pelo vetor até achar esse marcador.

Por isso "ENADE" ocupa 6 bytes (5 letras + o \0), embora strlen responda 5. E por isso == entre strings compara endereços, não o texto: para comparar o conteúdo use strcmp(a, b) == 0.

String em C é um vetor de char terminado em '\0'.

char s[] = "ENADE";
strlen(s);   // 5: não conta o '\0'
sizeof(s);   // 6: conta o '\0'

Comparar strings com == compara endereços, não o texto. O certo é strcmp(a, b) == 0.

Exemplo passo a passo

Conte os caracteres com um laço

  1. char s[] = "casa"; s[0] = 'C'; → o vetor agora é C a s a \0.
  2. int n = 0; while (s[n] != '\0') n++; → n passa por 0, 1, 2, 3 e para ao achar o \0 em s[4].
  3. Resultado: n = 4, e printf("%s", s) imprime Casa.
  4. Já char *t = "casa"; t[0] = 'C'; é erro: a string literal fica em memória só de leitura.
Como cai no ENADE

Costuma cair em trechos que percorrem uma string com laço, contam ou invertem caracteres, e em perguntas sobre strlen x sizeof e sobre comparar strings.

Operadores que confundem

Entenda o assunto

Muitas questões de C não testam lógica difícil, e sim detalhes dos operadores. Os quatro que mais pegam: a divisão entre inteiros joga fora a parte decimal; i++ usa o valor e depois soma, enquanto ++i soma e depois usa; = atribui e == compara; e && e || param assim que o resultado é conhecido (curto-circuito).

Quando houver mistura de operadores, siga a precedência e, em empate, a ordem da esquerda para a direita: multiplicação, divisão e resto antes de soma e subtração. Em dúvida, escreva os parênteses que o compilador "enxerga".

Exemplo passo a passo

O que valem j, k e i?

  1. int i = 3;
  2. int j = i++; → j recebe o valor antes do incremento: j = 3, e depois i = 4.
  3. int k = ++i; → i sobe antes: i = 5 e k = 5.
  4. Saída de printf("%d %d %d", j, k, i);: 3 5 5.
  5. Bônus: 7 / 2 * 2.0 é (7/2)=3 e depois 3 * 2.0 = 6.0 (a divisão acontece primeiro, ainda entre inteiros).
Como cai no ENADE

É o campo das pegadinhas de saída de código: pré e pós-incremento, divisão inteira, if (x = 0) e curto-circuito. Leia cada linha com calma e anote o valor das variáveis a cada passo.

Recursão

Entenda o assunto

Uma função é recursiva quando chama a si mesma para resolver um pedaço menor do mesmo problema. Toda recursão precisa de duas partes: o caso base (quando parar, sem chamar de novo) e o passo recursivo (chamar com um problema menor). Sem caso base ela nunca termina e estoura a pilha.

Para rastrear, pense em duas fases. Na descida, as chamadas ficam empilhadas esperando o resultado das seguintes. No caso base, surge o primeiro valor e começa a volta: cada chamada recebe o resultado da de cima, faz sua conta e devolve.

int f(int n) { if (n <= 1) return 1; return n * f(n - 1); }
int g(int n) { if (n == 0) return 0; return n % 10 + g(n / 10); }
  • f(4) = 4 × 3 × 2 × 1 = 24 (fatorial).
  • g(1234) = 4 + 3 + 2 + 1 + 0 = 10 (soma dos dígitos: % 10 pega o último dígito e / 10 o remove).
Exemplo passo a passo

Rastreie fatorial e Fibonacci

  1. f(3) com f(n) = n * f(n-1) e f(1) = 1: desce f(3) → f(2) → f(1).
  2. Volta: f(1) = 1; f(2) = 2 × 1 = 2; f(3) = 3 × 2 = 6.
  3. Fibonacci com fib(0)=0, fib(1)=1, fib(n)=fib(n-1)+fib(n-2): fib(2) = 1; fib(3) = fib(2)+fib(1) = 2; fib(4) = fib(3)+fib(2) = 2+1 = 3.
  4. Esse cálculo de fib(4) faz 9 chamadas, repetindo trabalho: por isso o Fibonacci recursivo simples é O(2ⁿ).
Como cai no ENADE

Cai como "o que retorna f(n)" (fatorial, soma de dígitos, potência) e como análise de complexidade ou da recorrência de uma função recursiva. Desenhe a árvore de chamadas.

Variável static

Entenda o assunto

Uma variável local comum nasce quando a função começa e morre quando ela termina: a cada chamada, começa do zero. Uma variável local declarada com static é criada uma única vez e mantém o valor entre as chamadas, como um caderninho que a função guarda para si.

Detalhe importante: a inicialização de uma static (static int b = 0;) acontece só na primeira vez. Nas chamadas seguintes essa linha é ignorada. Fora de funções, static em uma variável global significa "visível só neste arquivo".

Uma variável local static mantém o valor entre chamadas.

int conta() { static int c = 0; c++; return c; }
conta(); conta();
printf("%d", conta());   // 3
Exemplo passo a passo

O que imprime ao chamar f() três vezes?

  1. void f() { int a = 0; static int b = 0; a++; b++; printf("%d %d ", a, b); }
  2. 1ª chamada: a = 0→1; b = 0→1. Imprime 1 1.
  3. 2ª chamada: a recomeça em 0→1; b continua de onde parou, 1→2. Imprime 1 2.
  4. 3ª chamada: a = 1; b = 3. Imprime 1 3.
  5. Saída total: 1 1 1 2 1 3.
Como cai no ENADE

Cai em questões de saída com contadores dentro de funções. A regra de ouro: a variável comum zera a cada chamada; a static lembra.

Laços aninhados

Entenda o assunto

Em um for (início; condição; passo) a ordem é: executa o início uma vez, testa a condição, executa o corpo, executa o passo, e volta a testar. Se a condição for falsa logo de cara, o corpo nunca roda. break sai do laço; continue pula para a próxima volta.

No switch, depois de entrar em um case o programa continua executando os seguintes até achar um break (isso se chama "fall through"). Quase toda pegadinha de switch está em um break esquecido.

int cnt = 0;
for (int r = 0; r < 4; r++)
    for (int c = r; c < 4; c++)
        cnt++;
// cnt = 4 + 3 + 2 + 1 = 10

Quando o laço interno começa no contador do externo, a contagem vira uma soma decrescente. Isso também aparece em questões de complexidade: n + (n − 1) + ... + 1 = n(n + 1)/2, ou seja, O(n²).

Exemplo passo a passo

Rastreie um switch e um for

  1. switch (x) com x = 2 e case 1: printf("A"); case 2: printf("B"); case 3: printf("C"); break; default: printf("D");
  2. Entra em case 2, imprime B; sem break, cai no case 3 e imprime C; o break encerra. Saída: BC.
  3. for (i = 1; i <= 10; i += 3) soma += i; → i vale 1, 4, 7 e 10 (o próximo seria 13 e a condição falha).
  4. soma = 1 + 4 + 7 + 10 = 22.
Como cai no ENADE

Cai com laços aninhados (contar quantas vezes uma linha executa, ligado à complexidade) e com switch sem break. Anote o valor do contador em cada volta.

Threads e concorrência

Entenda o assunto

Uma thread é uma linha de execução dentro de um processo. Todas as threads do mesmo processo compartilham a memória (variáveis globais e o heap), mas cada uma tem a sua própria pilha. Isso é prático para trocar dados, e perigoso: duas threads mexendo na mesma variável ao mesmo tempo geram uma condição de corrida (race condition).

O motivo é que até contador++ não é uma operação só: é ler, somar e gravar. Se duas threads fazem isso intercaladas, um incremento se perde. A solução é uma exclusão mútua: um mutex (ou semáforo) garante que só uma thread por vez execute o trecho crítico.

  • Região crítica: trecho do código que acessa dado compartilhado e precisa de proteção.
  • Deadlock: cada thread segura um recurso e espera o que a outra segura. Para evitar, adquira os locks sempre na mesma ordem.
  • Em C, as threads POSIX usam pthread_create, pthread_join e pthread_mutex_lock/unlock.
Pegadinhas comuns
  • Variáveis locais não são compartilhadas (cada thread tem a sua pilha); globais e static são.
  • O resultado de um programa com corrida pode mudar a cada execução: "às vezes dá certo" não significa que está correto.
  • Mutex protege contra corrida, mas, usado em ordem trocada por duas threads, causa deadlock.
Exemplo passo a passo

Por que dois contadores de 1000 podem dar menos de 2000?

  1. Duas threads executam contador++ 1000 vezes cada; o esperado é 2000.
  2. Intercalação ruim: T1 lê 5; T2 lê 5; T1 grava 6; T2 grava 6. Foram dois incrementos, mas o contador subiu só uma unidade.
  3. Repetindo isso muitas vezes, o total fica abaixo de 2000 e varia a cada execução.
  4. Correção: envolver o incremento com pthread_mutex_lock(&m) e pthread_mutex_unlock(&m). Agora cada incremento é indivisível e o resultado é 2000.
Como cai no ENADE

Concorrência cai como "o que pode acontecer com este programa" (condição de corrida, deadlock) e como escolha do mecanismo de sincronização. Dialoga com o tema de Sistemas operacionais.
